## 2024-09-10 - N+1 Queries from Hidden Modals in Lists
**Learning:** A common performance bottleneck in React apps using mapping (like list rendering) occurs when hidden modals that contain data-fetching logic (e.g., `useQuery`) are conditionally rendered solely via CSS (or structural returns like `if (!open) return null`) instead of not mounting at all. If the `enabled` prop on `useQuery` only checks for a valid `id`, mounting N instances of the modal (one per item in the list) triggers N redundant API requests on initial page load, significantly impacting performance and causing N+1 query problems on the frontend.
**Action:** When a modal component manages its own internal data fetching via hooks like `useQuery` and is rendered inside a mapped list, explicitly ensure the modal's internal `useQuery` requires its `open` or `isVisible` state to be true in the `enabled` condition (`enabled: open && !!id`), thereby completely preventing the query from firing until the user actually opens the modal.
