## 2025-02-23 - Prevent XSS in Next.js App Router with SSR
**Vulnerability:** A Cross-Site Scripting (XSS) vulnerability was found in `src/app/blogs/[id]/page.tsx` where user-generated blog post content was being rendered directly using `dangerouslySetInnerHTML={{ __html: post.content }}` without any sanitization.
**Learning:** Next.js uses Server-Side Rendering (SSR) or Server Components by default in the App Router. Using a standard browser-based DOM sanitization library like `dompurify` directly will fail during the server build or render phase because the `window` and `DOM` objects are not available. This is a common pitfall that can either lead to broken builds or developers skipping sanitization entirely.
**Prevention:** Always use an SSR-compatible HTML sanitization library, such as `isomorphic-dompurify`, when rendering raw HTML in a Next.js (or any SSR) application. It falls back to a simulated DOM on the server environment, safely preventing XSS while keeping the build robust.
